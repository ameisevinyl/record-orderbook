# Artwork Preview Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the unreliable browser-side "simulate print" feature, add a Send-to-Plant hard block for missing/unreadable required artwork (Save Project stays warning-only), and teach the frontend to recognize and display a plant-generated `_preview.jpg` image automatically on the next project reload.

**Architecture:** Four artwork modules (`labels.js`, `cover.js`, `inner-sleeve.js`, `inlay.js`) each lose their canvas-overlay simulate-print code and gain a small "if a preview image is in the fileMap, show it instead" step in their existing reload path. The checklist (`tracklist.js`) gains a `blocking` sub-class on two existing checklist items and a hard-refuse branch in the Send-to-Plant confirmation, gated by one new config flag.

**Tech Stack:** Plain ES2020+ JS, no new dependencies. `node --test` for the pure `previewFileName` addition; everything else is DOM wiring with no existing unit-test seam (this codebase only unit-tests `src/lib/*`, per its own convention — see Global Constraints).

**Spec:** `docs/superpowers/specs/2026-09-21-artwork-preview-pipeline-design.md`

## Global Constraints

- No runtime dependencies; `dist/index.html` stays a single self-contained file (no CDN, no build tooling beyond `build/build.js`'s plain concatenation).
- Every top-level name across `src/lib/*` + `src/modules/*` + `src/app.js` must stay globally unique — the build flattens them into one shared scope (see `build/build.js`'s header comment).
- `node --test tests/` must pass after every task. Baseline before this plan: 103 tests passing (100 pure-logic + 3 in `tests/browser.test.js`, which Task 8 deletes — expect 100, then +2 from Task 1's new tests = 102 by the end).
- `node build/build.js` must succeed after every task (catches flattening-time errors like duplicate top-level names).
- **This codebase does not unit-test DOM modules** (`src/modules/*`) — only `src/lib/*` is covered by `node --test`, by explicit project convention (see `CLAUDE.md`'s Architecture section). Tasks that touch `src/modules/*`/`src/app.js`/`src/index.html` are verified by: syntax check, full regression suite staying green, a successful build, and a manual read-through of the diff against this plan's exact code. **Do not spin up Chrome browser automation to live-verify a task by default — ask the user first before doing so**, per their standing preference (it's token-expensive); a task is done when the above checks pass and the diff matches this plan.
- **Save Project stays warning-only, unconditionally.** None of this plan's changes may make `saveProject()` (or anything it calls) refuse to save. The hard block is scoped to `sendToPlant()`/`confirmIncompleteSend()` only.
- Commit messages: short, imperative, no ceremony, precise — matching this repo's existing history (`git log --oneline` for examples).

// PNKRCK007_labels_A_v1_preview.jpg — same base name as

// plant's backend (not this tool) once it reviews the real file;
